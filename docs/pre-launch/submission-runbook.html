The archive

The worktree is prepared and verified. The ordering below is not fussiness — getting it wrong is what cost forty minutes last time.

Open only the archive project

/Users/stephenrussell/Projects/split-index-archive/ios/App/App.xcodeproj

Not the main checkout's project. Both resolve Swift packages through their own node_modules, and opening both is what produced "package already opened from another project".

Let package resolution finish before doing anything else.

Never delete DerivedData while Xcode is open

It regenerates immediately and half-written, which produces "no XCFramework found" across every package. If you need it cleared, quit Xcode first, then clear it, then reopen.

Product → Archive

Destination: Any iOS Device (arm64)

Not a simulator — a simulator build cannot be distributed and the Archive menu item stays disabled. Build 9, device family 1,2, already set in the project.

Distribute App → App Store Connect → Upload

Then wait for the processing email. The build does not appear in the version's Build selector until processing finishes, which is usually minutes but can be an hour.

Upload the 6.9" screenshots — this is why the App Store shows none

~/Documents/SplitIndex-Screenshots-6.9/ · five files, 1320×2868

The live listing has only 6.5" assets (1284×2778). Apple's pipeline treats 6.9" as the master and scales down from it, so with that slot empty there is nothing to scale and the search result renders with no images at all — which is exactly what you saw.

After uploading, delete the existing 6.5" set. It is in the wrong order (analytics first, dashboard fourth) and once 6.9" exists Apple scales from it automatically.

The gate: a real purchase

The only part of the payment chain never proven end to end. app-store-remaining.md is explicit: do not submit before this has been seen working once.

Webhook — already verified

RevenueCat's test webhook returned 200 {"received":true}. URL and shared secret are both correct, which removes the link most likely to be misconfigured.

Make one sandbox purchase on a device

  1. App Store Connect → Users and Access → Sandbox → Test Accounts → +. Use an email that has never been an Apple ID; a +alias works. Region United Kingdom.
  2. On the device: Settings → Developer → Sandbox Apple Account. Do not sign out of your real account.
  3. Open the paywall. If the prices do not render, stop — that is the products or the Paid Applications agreement, not the purchase.
  4. Buy the monthly. The sheet must say [Environment: Sandbox]; if it does not, cancel — that is real money.

Then check all four links, because each fails independently:

  • RevenueCat → Customers: split_index_pro shows as an active entitlement
  • RevenueCat → Webhooks: an INITIAL_PURCHASE event with a 2xx
  • Supabase → profiles: subscription_tier = premium and subscription_source = revenuecat
  • In the app: the Hybrid Plan unlocks — it is gated now, so it is the clearest yes/no

An App Preview video

The biggest remaining visual lift in search results — an app with one gets motion where everyone else gets stills. 15–30 seconds, 886×1920 portrait, H.264, under 500 MB. The existing review walkthrough is far too long and the wrong resolution.

The 29.7 personal score

Never reproduced. The closest reconstruction was 40.8, and closing the gap needs the actual session history. The tap-to-explain sheet now names which sessions it compared against and how alike they were, so the next odd number may explain itself.

The flat bottom of the bodyweight scale

Adding 0 to 10 kg to a pull-up moves the score 3.4 points; the next 10 kg moves 25.8. Two constant changes were tried and reverted — raising the floor traded one compression for another, and lowering the curvature runs opposite to intuition. It needs the band's shape reconsidered, not a constant nudged, and it only affects near-bodyweight reps.

blocked_users is not named in the privacy policy

Flagged by check-privacy-coverage.mjs, cited against Guideline 5.1.1(i) and UK GDPR art. 13. The table predates all of this and is already live; the checker that notices is what is new.
